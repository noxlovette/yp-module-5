## Что было сделано

### 1–3. Дефекты (найдены и исправлены)

| #   | Дефект                                    | Где                                                                          | Исправление                                                                                                            |
| --- | ----------------------------------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 1   | Off-by-one в подсчёте чётных чисел        | `sum_even`                                                                   | логика фильтра исправлена (commit `f8674a4`)                                                                           |
| 2   | Use-after-free / aliasing в `unsafe`-коде | мёртвая функция, нигде не вызывалась                                         | код удалён (commit `25582ea`)                                                                                          |
| 3   | Лишняя аллокация/утечка буфера            | `leak_buffer`: `input.to_vec().into_boxed_slice()` только ради подсчёта байт | считаем прямо по заимствованному срезу, без копий                                                                      |
| 4   | Неверная логика усреднения                | `average_positive` некорректно считал сумму/количество                       | переписано через `filter_map` + `fold` (issue [#5](https://github.com/noxlovette/yp-module-5/issues/5))                |
| 5   | Неэффективные алгоритмы                   | `slow_fib` (`O(2^n)`), `slow_dedup` (`O(n² log n)`)                          | см. оптимизации ниже                                                                                                   |
| 6   | Гонка данных между потоками               | `concurrency::race_increment`: `static mut COUNTER: u64` без синхронизации   | `COUNTER` заменён на `AtomicU64`, все операции — через `fetch_add`/`load`/`store` (`Ordering::SeqCst`), `unsafe` убран |

Дефект #6 изначально не был покрыт тестами, поэтому и `cargo test`, и ThreadSanitizer
проходили «чисто» просто потому, что гонку никто не вызывал. Добавлен тест
`race_increment_is_correct` (`tests/integration.rs`), который до фикса **падал примерно
в 40% запусков** (4 потока × 1000 инкрементов теряли часть обновлений из-за гонки) —
именно так дефект и был обнаружен как воспроизводимая проблема, а не только
теоретическая. После перехода на `AtomicU64` тест стабильно проходит (проверено 24/24
последовательных запусков) и TSan теперь действительно покрывает этот код путь, а не
просто пропускает его.

### 4–5. Профилирование и бенчмарки «до»

- `cargo flamegraph` (dtrace, macOS) на `benches/baseline.rs` выявил горячие пути:
  `slow_fib` (55.9% сэмплов), `slow_dedup` (35.3%, включая накладные расходы от
  сортировки на каждой вставке), `sum_even` — контрольная функция, в сэмплы не попала.
- `benches/criterion.rs` параметризован по двум размерам входа на группу, чтобы в
  цифрах была видна асимптотика.
- Результаты сохранены в `broken-app/artifacts/`: `baseline_before.txt`,
  `baseline_before_criterion.txt`, `criterion_before/` (полная копия отчётов
  `target/criterion`), `flamegraph-init.svg`.

### 6. Оптимизация

| Функция                     | Было                                                        | Стало                                               | Тип                                |
| --------------------------- | ----------------------------------------------------------- | --------------------------------------------------- | ---------------------------------- |
| `slow_fib` → `fast_fib`     | `O(2^n)` рекурсия без мемоизации                            | `O(n)` время / `O(1)` память, итеративно            | алгоритмическая                    |
| `slow_dedup` → `fast_dedup` | `O(n² log n)`: линейный скан + сортировка на каждой вставке | `O(n log n)`: `HashSet` + одна финальная сортировка | алгоритмическая / структуры данных |
| `leak_buffer`               | лишняя аллокация+копия ради подсчёта                        | проход по срезу без копий                           | микро (alloc)                      |

`unsafe` не потребовался ни в одной из оптимизаций.

### 7. Проверка «после»

**Корректность** — все проверки повторены после оптимизаций, без регрессий:

| Проверка                                                                  | Команда                                                                                                        | Результат                             |
| ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| `cargo test`                                                              | `cargo test`                                                                                                   | 10/10 ok                              |
| Miri                                                                      | `cargo +nightly miri test`                                                                                     | 10/10 ok, без предупреждений          |
| AddressSanitizer _(замена Valgrind — не поддерживается на Apple Silicon)_ | `RUSTFLAGS="-Z sanitizer=address" cargo +nightly test --target aarch64-apple-darwin`                           | 10/10 ok                              |
| ThreadSanitizer                                                           | `RUSTFLAGS="-Z sanitizer=thread" cargo +nightly test --target aarch64-apple-darwin -Z build-std --lib --tests` | 10/10 ok, без предупреждений о гонках |

**Производительность** (полные таблицы и файлы — в [`PROFILING.md`](PROFILING.md)):

| Бенчмарк                          | До        | После     | Ускорение                 |
| --------------------------------- | --------- | --------- | ------------------------- |
| `fib(28)`                         | 611.64 µs | 7.08 ns   | **≈86 400×**              |
| `fib(34)`                         | 10.929 ms | 8.41 ns   | **≈1 300 000×**           |
| `dedup(2 000)`                    | 995.32 µs | 20.04 µs  | **≈50×**                  |
| `dedup(20 000)`                   | 93.081 ms | 219.59 µs | **≈424×**                 |
| `sum_even` (контроль, не менялся) | —         | —         | в пределах шума измерений |

Ускорение растёт вместе с размером входа для `fib`/`dedup` — это ожидаемо при переходе
на лучшую асимптотику и подтверждает, что эффект алгоритмический, а не шум измерений
(контрольная `sum_even` осталась без изменений).

## Как воспроизвести

```bash
cd broken-app

cargo test                                   # корректность
cargo +nightly miri test                     # UB
RUSTFLAGS="-Z sanitizer=address" \
  cargo +nightly test --target aarch64-apple-darwin                       # ASan
RUSTFLAGS="-Z sanitizer=thread" \
  cargo +nightly test --target aarch64-apple-darwin -Z build-std --lib --tests  # TSan

cargo bench --bench baseline                 # быстрые «до/после» тайминги
cargo bench --bench criterion                # статистически устойчивые бенчмарки + HTML-отчёты
```

Подробный журнал по каждому шагу — в [`PROFILING.md`](PROFILING.md).

## P.S.

Valgrind не поддерживается на Apple Silicon. Вместо него использовались
AddressSanitizer и LeakSanitizer.
